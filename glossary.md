# Glossary

Terms as this course uses them. Lesson ids in brackets point to where a term is taught.

- **1F1B** — the pipeline schedule that alternates one forward and one backward after a warm-up, holding at most p - s micro-batches on stage s. [09.2]
- **2-D weight scaling** — one scale per square block (16 × 16 in NVFP4) so a weight and its transpose quantise identically and the forward and backward passes see the same weight. [08.3]
- **A/A test** — comparing two replicates of the same method; any "significant" difference shows what noise alone produces. [01.4]
- **Acceptance rate** — the share of drafted tokens the verifier accepts; with acceptance p and D drafts a round yields 1 + p + … + p^D tokens. [06.1]
- **Activation checkpointing (recomputation)** — saving only a block's input and recomputing its forward during backward, trading about one extra forward per block for memory. [02.2]
- **Activation memory** — the forward tensors autograd keeps for the backward pass; measured in the course with saved-tensor hooks. [02.2]
- **Active parameters** — the parameters one token uses in a forward pass (shared layers plus the routed experts it is sent to). Labs differ on whether the input embedding, output head and MTP layers count; recompute from the config before comparing. [01.2]
- **Additive prediction** — the combination's expected result if effects simply add: baseline plus the sum of single-change effects. [06.3]
- **Advantage** — reward minus a baseline that does not depend on the sampled response; it weights the response's log-probability gradient. [12.2]
- **Advertised context length** — the length a model accepts or was trained at (`max_position_embeddings`), regardless of whether it uses that context. [04.1]
- **Allocation exponent** — the a in N_opt ∝ C^a; about 0.5 in Chinchilla, 0.73 in Kaplan et al. before the reconciliation. [11.1]
- **Allocation ratio (ρ)** — the share of the inactive parameter budget kept as routed experts, the rest going to Engram tables; the Engram paper reports a U-shaped loss with an optimum near ρ ≈ 75–80%. [06.4]
- **amax** — the largest absolute value of the group of elements that share a scale. [08.1]
- **Amax gain** — mHC's diagnostic: the maximum absolute row sum (forward) or column sum (backward) of the composite residual mapping across layers. [06.2]
- **Amdahl's law** — speeding up a fraction f of the work by k gives an overall time of (1 − f) + f/k. [02.4]
- **Anneal (mid-training)** — the final phase of pretraining in which the learning rate decays to zero, usually on a higher-quality mix. [10.4]
- **ArchSpec** — `frontierlab.calc`'s normalised description of a model read from a Hugging Face config.json, with the config key behind every field. [01.2]
- **Arithmetic intensity** — FLOPs an operation performs per byte it moves between memory and the chip; compared with the ridge point it says whether the op is compute- or memory-bound. [02.1]
- **Attention sink** — a token, usually the first, on which attention heads place large probability regardless of its content, because each softmax row must sum to one. [03.3]
- **Attention temperature (YaRN)** — multiplying q and k by 0.1 ln s + 1 (logits by its square) to re-sharpen attention after interpolation. [04.2]
- **Attention-mass recall** — the share of a query's attention probability that falls on a chosen set of keys; used to compare a selector with the oracle top-k and a sliding window. [05.2]
- **Banded causal mask** — the mask allowing key j for query i exactly when q_i − w < k_j ≤ q_i (positions), used by sliding-window layers. [03.2]
- **Base width** — the width at which µP and SP coincide; µP's factors are stated relative to it (m = width / base width). [07.3]
- **Base-frequency adjustment** — raising the RoPE base (`rope_theta`) so that every pair rotates more slowly and covers a longer context (Llama 3 uses 500,000). [04.2]
- **Batch invariance** — a kernel property: a row's result does not depend on how many other rows are in the batch; its absence is the main cause of nondeterministic LLM inference (Thinking Machines, 2025). [01.5]
- **Benchmark leakage** — evaluation items, or large parts of them, present in the training data; measured here by word n-gram overlap with a training index. [10.1]
- **Best-of-n (BoN)** — sample n responses and keep the one a reward scores highest; its KL from the base policy is log n - (n-1)/n. [12.1]
- **Binade** — the range [2^k, 2^(k+1)); a binary float has evenly spaced values inside each binade, 2^(k − m) apart for m mantissa bits. [08.1]
- **Birkhoff polytope** — the set of doubly-stochastic matrices, the convex hull of the permutation matrices. [06.2]
- **Bitwise reproducibility** — identical bits from a rerun; achievable only with fixed code, software, hardware type and parallel layout. Contrast with statistical reproducibility (within the noise floor). [01.5]
- **Block scaling** — one scale per small group (a row, a 1 × 128 tile, a 128 × 128 or 16 × 16 block, 32 or 16 consecutive values) instead of per tensor, so one outlier affects only its group. [08.1]
- **Bradley-Terry loss** — -log sigmoid(r(chosen) - r(rejected)), the likelihood of pairwise preferences under the Bradley-Terry model. [12.1]
- **Bus bandwidth** — a collective's bytes moved per rank divided by its time (all-reduce: 2(n−1)/n × size / time); comparable across rank counts. [02.3]
- **Byte Latent Transformer (BLT)** — a byte-level model whose large latent transformer runs once per variable-length patch, with small local models encoding and decoding bytes. [06.6]
- **Capability retention** — performance on skills a post-training stage did not train, measured to catch regressions. [12.4]
- **Chinchilla form** — L(N, D) = E + A/N^α + B/D^β: an irreducible loss plus what a finite model and a finite dataset add (Hoffmann et al.). [11.1]
- **Chunked (fused linear) cross-entropy** — computing the loss and its gradients a block of rows at a time so the full (B, T, V) logits tensor is never materialised. [02.2]
- **Chunked-parallel form** — computing a linear-attention recurrence C tokens at a time with matrix products and a triangular solve inside each chunk and the state carried between chunks; exactly equal to the recurrence. [05.1]
- **Clip-higher** — an asymmetric clip range with a larger upper bound (DAPO 0.2 / 0.28) so unlikely tokens with positive advantage can grow. [12.3]
- **Cloze multiple choice** — a task built from held-out text: the true continuation of a context against continuations taken from other documents, scored by log-probability. [11.2]
- **Comparison axis** — what two arms are held equal on: tokens, parameters, training FLOPs or wall-clock; each answers a different question. [01.3]
- **Compressed Sparse Attention (CSA)** — DeepSeek-V4's attention that compresses every m tokens into one KV entry (overlapping), selects the top-k compressed entries with an indexer and adds an uncompressed sliding window. [05.4]
- **Compute-optimal** — the model size and token count that minimise loss for a fixed training compute C ≈ 6·N·D. [11.1]
- **Compute-optimal precision (P*)** — the training precision that minimises loss at fixed compute when parameters, tokens and bits are chosen together; about 7–8 bits in Kumar et al.'s integer-type fits. [08.4]
- **Conditional memory** — sparse capacity reached by lookup rather than computation: a few rows of a large table, chosen by the input, are read per token. [06.4]
- **Context gain** — loss with the context cut to the last W tokens minus loss with the full context, for the same target tokens, paired by document; positive means the far tokens are used. [04.1]
- **Context parallelism (CP)** — splitting each sequence over devices; attention then needs the other pieces' keys and values (ring or all-gather). [09.1]
- **Continued training** — training a finished model further on data chosen for a target (domain, language, skill, length). [10.5]
- **Continuous thought (Coconut)** — feeding the model's last hidden state back as the next input embedding instead of decoding it to a token. [06.7]
- **Cooldown** — another name for the final decay of a WSD schedule; Hägele et al.'s 1-sqrt cooldown uses f(u) = 1 − √u. [07.4]
- **Coordinate check** — training a few steps at several widths and checking that activation sizes and their changes do not grow or shrink with width; the standard test of a µP implementation. [07.3]
- **Counter-based RNG** — random numbers derived from (seed, step, global sample index) instead of a per-rank generator state, so they do not depend on the layout. [09.4]
- **Counter-based sampler** — a data sampler whose window k is a pure function of k and the mixture spec, so resume is a seek and token accounting is exact. [10.1]
- **Cross-split near-duplicate** — a held-out document whose shingle set has a high Jaccard similarity with a training document, although its hash (and so its split) differs. [10.1]
- **Crossover context** — the context length at which a sub-quadratic design becomes faster than dense attention on a given machine and kernel. [05.3]
- **Data manifest** — the source records of a mixture with its weights, shared tokenizer and licence summary, stored next to the run cards of every run trained on it. [10.1]
- **Data mixing law** — L_i(r) = c_i + k_i·exp(Σ_j t_ij r_j): a fitted function from training proportions r to validation loss on domain i (Ye et al.). [10.4]
- **Decay branch** — a run that starts from a full checkpoint of a stable (constant-learning-rate) run and decays from there; several lengths share one stable trunk. [07.4]
- **Decision rule** — the pre-stated mapping from an interval to adopt / reject / inconclusive, written before the runs. [01.3]
- **Decoupled RoPE key** — MLA's separate, small key of width d_r that carries the rotary position signal and is shared by all heads, so the content key's up-projection can still be absorbed. [03.1]
- **DeepSeek Sparse Attention (DSA)** — DeepSeek-V3.2's attention in which a lightning indexer scores every earlier token and the main attention runs over the top-k (2,048) tokens only. [05.2]
- **Delta rule** — a state update that first reads what the memory returns for the current key and then moves it a fraction β toward the new value, so a key written twice keeps only the latest value. [05.1]
- **Dense warm-up** — the first DSA training stage: dense attention, every parameter frozen except the indexer, which learns to match the main attention. [05.2]
- **Document masking** — an attention mask that stops tokens in a packed window from attending across document boundaries. [04.3]
- **Doubly-stochastic matrix** — a non-negative matrix whose rows and columns each sum to 1; products of such matrices stay doubly stochastic and their spectral norm is at most 1. [06.2]
- **DualPipe / DualPipeV** — DeepSeek's bidirectional pipeline schedules that overlap a forward and a backward chunk to hide expert all-to-all; DualPipe keeps two parameter copies per device, DualPipeV runs the stages in a V on half the devices. [09.2]
- **E2M1 (FP4)** — the 4-bit float with values ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}; usable only with a scale per small block of values. [08.1]
- **E4M3** — the FP8 format with 4 exponent and 3 mantissa bits (bias 7): largest value 448, smallest normal 2^-6, smallest subnormal 2^-9, no infinities, one NaN pattern; the usual format for weights and activations. [08.1]
- **E5M2** — the FP8 format with 5 exponent and 2 mantissa bits (bias 15): largest value 57,344, IEEE infinities and NaNs; more range, less precision than E4M3; traditionally used for gradients. [08.1]
- **E8M0 / UE8M0** — an 8-bit unsigned exponent with no mantissa, storing a power-of-two scale 2^(E − 127); the scale format of the OCP MX formats and of DeepSeek-V3.1. [08.1]
- **Effective context length** — the longest length at which a stated score stays above a stated threshold at that length and every shorter one (RULER's definition, with the threshold fixed in advance). [04.1]
- **Effective data** — the fresh-token worth of repeated data, D' = U + U·R*·(1 − e^(−R/R*)) for U unique tokens repeated R times (Muennighoff et al.). [11.1]
- **Effective parameter count (N_eff)** — in the precision scaling law, the parameter count a low-precision-trained model behaves like: N(1 − e^(−P/γ)). [08.4]
- **Emergent ability** — an ability "not present in smaller models but present in larger models" (Wei et al.); often an artefact of an all-or-nothing metric (Schaeffer et al.). [11.2]
- **Emulation (of a low-precision format)** — reproducing a format's rounding exactly in a higher-precision dtype; it measures numerics, never speed. [08.1]
- **Engram** — DeepSeek's conditional-memory module: hashed suffix N-grams index embedding tables; the retrieved vector is gated by the hidden state, filtered by a causal convolution and added to the residual at a few layers. [06.4]
- **Entropy collapse** — the fast fall of policy entropy during RL, which Cui et al. relate to a ceiling on further reward gains. [12.2]
- **Entropy patching** — starting a new patch where a small byte model's next-byte entropy exceeds a threshold (global rule) or jumps up (monotonic rule). [06.6]
- **Equal-parameters arm** — a variant whose FFN width is adjusted so its non-embedding parameter count equals the baseline's, removing model size as a confound. [03.1]
- **Equal-token control** — continuing the base model at its original length for the same tokens, seed and schedule as an extension arm, to separate the effect of longer context from the effect of more training. [04.3]
- **Equal-work comparison** — a performance comparison in which both arms process the same tokens with the same model and shapes. [02.4]
- **Eval Suite v0** — the course's first evaluation: held-out loss on fixed Data-v0 windows plus LAMBADA last-word prediction (pinned revision), scored per item for pairing. [Module 1 project]
- **Eval Suite v2** — the course's evaluation after every post-training stage: task (pass@1, pass@k), capability retention and instruction following, scored per item and compared with paired intervals. [12.4]
- **Evidence effect** — paired mean of the answer's candidate-normalised log-probability with the evidence minus without it; cancels the model's prior over candidate words. [04.1]
- **Evidence label** — PUBLICLY DOCUMENTED (with location), REASONABLE INDUSTRY PRACTICE, INFERENCE/SPECULATION or (company claim): how much a statement in the course can be trusted and why. [01.2]
- **Evidence-ablated twin** — a synthetic item with the statements that contain the answer replaced by filler of the same length; the model's accuracy on it must be at chance. [04.1]
- **Expected calibration error (ECE)** — the item-weighted mean gap between predicted probability and observed frequency over probability bins. [12.1]
- **Expert parallelism (EP)** — placing the routed experts of each MoE layer on different devices and moving tokens to them with all-to-all. [09.1]
- **Exposed communication** — the part of a step's time caused by communication that computation did not hide: step time with sync minus without. [02.3]
- **Factorial-lite design** — baseline, every single change, the full combination and the combination with each change left out (at most 2k + 2 cells) instead of all 2^k cells. [06.3]
- **Fake quantisation** — quantise-then-dequantise in a higher-precision dtype, so a model computes with low-precision values without low-precision kernels. [08.3]
- **Fine-grained quantisation (DeepSeek-V3)** — FP8 with 1 × 128 activation tiles (128 × 1 in the backward pass) and 128 × 128 weight blocks, E4M3 everywhere, FP32 scales. [08.2]
- **First-token mass** — the average attention probability queries place on the first key of the window; compared with the uniform-attention baseline to detect a sink. [03.3]
- **Forgetting** — the loss a continued-training run adds on general held-out data, measured against an equal-token control on general data. [10.5]
- **FP32 promotion (N_C)** — adding a GEMM's partial sum to an FP32 accumulator every N_C elements (128 in DeepSeek-V3) because the tensor-core FP8 accumulator keeps only about 14 bits. [08.2]
- **Fprop / Dgrad / Wgrad** — the three GEMMs of a linear layer in training: the forward product, the gradient with respect to the input, and the gradient with respect to the weight; each contracts over a different dimension. [08.2]
- **FSDP2 (fully_shard)** — PyTorch's per-parameter sharded data parallelism: parameters sharded as DTensors, all-gathered per module for forward and backward, gradients reduce-scattered. [02.3]
- **Gated attention (output gating)** — multiplying each head's attention output by a sigmoid of the normalised layer input before the output projection (Qwen, position G1). [03.3]
- **Gated DeltaNet** — linear attention with the delta rule and one data-dependent decay per head and token; the linear layer family of Qwen3-Next. [05.1]
- **Gather traffic** — the memory traffic of copying or reading the k selected key-value entries per query in sparse attention; memory-bound unless entries are shared across heads or queries. [05.3]
- **Generalised advantage estimation (GAE)** — per-token advantages as an exponentially weighted sum of temporal-difference errors of a value model. [12.2]
- **Generator compute** — the forward FLOPs of producing synthetic data, counted as part of the cost of the runs that use it. [10.3]
- **Go/no-go checklist** — the pre-stated checks (fit error on held-out runs, interior minima, transfer, interval width, extrapolation distance) that must pass before an expensive run is launched. [11.3]
- **Gold reward** — in an over-optimisation experiment, the held-out reward that stands in for true preferences and that the proxy never sees directly. [12.1]
- **Goodput** — the fraction of wall-clock time spent on useful training progress, after checkpoint writes, lost work and restarts. [09.4]
- **Gradient bucket** — a group of gradients DDP all-reduces together; buckets are launched as soon as their gradients are ready so communication overlaps backward. [02.3]
- **Group baseline** — a baseline built from the other responses sampled for the same prompt (group mean in GRPO, leave-one-out in RLOO). [12.2]
- **Group normalisation** — dividing advantages by the group's reward standard deviation (GRPO); Dr. GRPO calls the resulting weighting a question-difficulty bias. [12.2]
- **Growth exponent** — the slope p of log time against log context (time ≈ a·L^p); 2 for quadratic, 1 for linear, 0 when fixed costs dominate. [05.3]
- **Heavily Compressed Attention (HCA)** — DeepSeek-V4's attention that compresses every m' ≫ m tokens into one entry without overlap and attends densely over all of them. [05.4]
- **HFU (hardware FLOPs utilization)** — like MFU but counting the FLOPs actually executed, including recomputation; higher than MFU under activation checkpointing. [02.1]
- **Holm correction** — step-down adjustment of several p-values that controls the chance of any false claim. [01.4]
- **Hybrid layout (N:1)** — a stack in which N linear-attention layers alternate with one full-attention layer (3:1 in Qwen3-Next and Kimi Linear). [05.1]
- **Hybrid Newton–Schulz** — DeepSeek-V4's 10-step schedule: 8 quintic steps for fast growth, then 2 steps with (2, −1.5, 0.5), whose stable fixed point at 1 makes the singular values exact. [07.2]
- **Hyper-connections (HC)** — an n-stream residual with learned read (H_pre), write (H_post) and stream-mixing (H_res) mappings around every sub-layer, each a static bias plus an input-dependent term. [06.2]
- **Identity path** — the bare residual term that carries a layer's input unchanged to deeper layers; in HC it becomes a product of learned mixing matrices. [06.2]
- **IFEval** — a benchmark of 541 prompts with 25 types of verifiable format instructions, scored prompt-level and instruction-level, strict and loose. [12.4]
- **Importance ratio** — pi_theta(token) / pi_old(token), which reweights samples drawn by an older policy; PPO clips it. [12.3]
- **Indexer KL objective** — the loss that trains the indexer: KL divergence from the head-summed, L1-normalised main attention distribution to the softmax of the index scores. [05.2]
- **Inference-aware sizing** — choosing size and tokens to minimise training plus lifetime inference FLOPs instead of training FLOPs alone (Sardana et al.). [11.1]
- **Interaction (contrast)** — in a 2 × 2 design, m11 − m10 − m01 + m00: how much one change's effect differs when the other is present; zero means the effects add. [06.3]
- **Interleaved 1F1B** — 1F1B with v non-adjacent chunks per device, which divides the bubble by v at the cost of more messages and first-stage memory. [09.2]
- **Interleaved benchmark** — timing the arms of a comparison alternately within each round so drift affects both equally; analysed with a paired speed-up. [02.4]
- **iRoPE** — Meta's name for Llama 4's interleaving of attention layers without positional embeddings among RoPE layers, with inference-time attention temperature scaling. [04.2]
- **Iso-FLOP profile** — loss against model size for runs that all spend the same compute; its minimum is the compute-optimal size at that budget (Chinchilla's approach 2). [11.1]
- **Job MTBF** — the mean time between interruptions of a whole job; with N independent devices it is the per-device MTBF divided by N. [09.4]
- **k1, k2, k3 estimators** — per-token KL estimators delta, delta^2/2 and exp(-delta) - 1 + delta with delta = log pi - log pi_ref; used as loss terms their expected gradients are zero, the reverse-KL gradient and the forward-KL gradient. [12.2]
- **Kernel fusion** — computing a chain of elementwise ops in one kernel so the data is read and written once instead of once per op. [02.2]
- **Kimi Delta Attention (KDA)** — the gated delta rule with a separate decay for every key channel (channel-wise gating), used in Kimi Linear. [05.1]
- **KL in the reward vs KL in the loss** — subtracting a detached KL estimate from the reward (InstructGPT) versus adding a differentiated KL term to the loss (GRPO). [12.2]
- **KV latent (c_KV)** — MLA's per-token compressed vector of width d_c (`kv_lora_rank`), the main thing its decode cache stores. [03.1]
- **Launch-bound** — a GPU step whose kernels are short compared with the CPU cost of launching them, so the GPU idles between kernels. [02.2]
- **Learned sink logit** — a per-head scalar added to the softmax denominator with no value attached, letting a head attend to nothing (gpt-oss). [03.3]
- **Learning-rate sensitivity** — the mean excess loss over a learning-rate sweep relative to its best rate, capped at the initial loss (Wortsman et al.). [11.3]
- **Leave-one-out baseline (RLOO)** — the mean reward of the other G-1 responses of the group; unbiased, and equal to G/(G-1) times the group-mean advantage. [12.2]
- **Length bias** — the per-token discount long responses get under per-response normalisation, so long wrong answers are penalised less per token. [12.3]
- **Lexical decoy** — a distractor statement that shares the query's key under another prefix, so a model that only matches the key picks it as often as the answer. [04.1]
- **Lightning indexer** — DSA's small scorer, a weighted sum over a few heads of ReLU(q·k), cheap per pair (few heads, FP8) but computed for every (query, key) pair. [05.2]
- **Linear attention** — attention without the softmax, which lets each head keep one d_k × d_v state matrix updated once per token instead of a cache that grows with the context. [05.1]
- **Load-balanced CP sharding** — giving rank r chunks r and 2n-1-r of 2n equal chunks so every rank has the same causal work. [09.1]
- **Local/global interleaving** — a layer layout that alternates sliding-window layers with full-attention layers (Gemma 3: 5 local per global; gpt-oss: alternating). [03.2]
- **Logit soft-capping** — replacing a logit ℓ by c · tanh(ℓ/c) so it never exceeds c (Gemma 2: 50 in attention, 30 on the final layer). [07.5]
- **Loss aggregation** — how per-token losses are combined (per-response mean, token mean, constant normaliser, prompt mean); it sets each token's weight. [12.3]
- **Loss mask** — the per-token indicator of which positions are in the policy loss: response tokens up to and including EOS. [12.3]
- **Loss spike** — a step whose loss exceeds the recent median by more than a noise-adapted threshold (here max(6 · 1.4826 · MAD, 5% of the median)). [07.5]
- **Lost in the middle** — the drop in long-context performance when the relevant information sits in the middle of the context rather than near its start or end. [04.1]
- **Low-confidence remasking** — a masked-diffusion sampler that commits the most confident predictions each step and masks the rest again. [06.7]
- **Manifold-constrained hyper-connections (mHC)** — HC with H_res projected onto doubly-stochastic matrices by Sinkhorn-Knopp and non-negative read/write mappings, so the composite identity path neither grows nor shrinks. [06.2]
- **Masked diffusion language model** — a bidirectional mask predictor trained to recover tokens masked at a random rate t, with a 1/t-weighted loss that bounds the negative log-likelihood (LLaDA). [06.7]
- **Massive activations** — a few hidden-state entries far larger than the rest, nearly constant across inputs, that act as biases and coincide with attention sinks. [03.3]
- **Matched filtering ablation** — models trained at equal tokens on filtered and unfiltered versions of the same pool, compared by seed on held-out sets the filter does not target. [10.2]
- **MatFormer** — a transformer whose FFN neurons are nested so that every prefix width is a usable sub-model; trained by sampling one width per step. [06.5]
- **Maturity tag** — ESTABLISHED, PROMISING or MODEL-SPECIFIC: how widely a technique has been adopted and independently supported. [01.2]
- **Maximum attention logit (S_max)** — per head, the largest pre-softmax score q·k/√d over a batch; the statistic QK-Clip and stability logs watch. [07.2]
- **Memory snapshot** — a record of every CUDA allocation with its stack (`torch.cuda.memory._record_memory_history` / `_dump_snapshot`), viewed at pytorch.org/memory_viz. [02.2]
- **Memory-bound / compute-bound** — an op limited by bytes moved (intensity below the ridge) or by arithmetic (above it). [02.1]
- **MFU (model FLOPs utilization)** — the FLOPs the model needs per second (tokens/s × training FLOPs per token) divided by the hardware's dense peak; excludes recomputation. [02.1]
- **Micro-anneal** — a short annealing run on a 50/50 mix of a candidate dataset and the general mix, compared with a control anneal to score the candidate (OLMo 2). [10.4]
- **Microscaling (MX) formats** — OCP's MXFP8, MXFP6, MXFP4 and MXINT8: 32 elements share one E8M0 power-of-two scale (OCP MX v1.0). [08.1]
- **Minimum detectable effect (MDE)** — the smallest true difference a design detects with a given power and level; for two arms, (z₁₋α/₂ + z₁₋β)·σ·√(2/n). [01.4]
- **Mix'n'Match** — choosing a different nested width per layer at inference to hit a compute budget, with widths that grow slowly with depth. [06.5]
- **Model collapse** — the narrowing of a model's output distribution (tails disappearing) when models are trained recursively on generated data. [10.3]
- **Model ladder** — a set of small runs with the target's exact recipe, at several sizes and token ratios, used to predict and de-risk the target run. [11.3]
- **MTP loss weight (λ)** — the factor on the averaged MTP loss; DeepSeek-V3 uses 0.3 for the first 10T tokens and 0.1 for the remaining 4.8T. [06.1]
- **Multi-head hashing** — hashing each key with several independent functions into separate tables, so a key that collides in one table is likely clean in another. [06.4]
- **Multi-head Latent Attention (MLA)** — attention that caches a compressed latent per token (plus one shared RoPE key) instead of per-head keys and values (DeepSeek-V2/V3, Kimi K2). [01.2]
- **Multi-query attention (MQA)** — attention in which all query heads share a single key and value head; GQA with one KV group. [03.1]
- **Multi-token prediction (MTP)** — training extra prediction modules to predict tokens beyond the next one, as an additional loss; at inference the modules are dropped or reused as a speculative-decoding draft. [06.1]
- **Muon** — an optimizer for 2-D hidden weight matrices: SGD momentum (Nesterov), then an approximate orthogonalisation of the update by a Newton–Schulz iteration, then a shape-dependent scale; embeddings, the output head and vectors stay on AdamW. [07.1]
- **MuonClip** — Muon with weight decay, update-RMS matching and QK-Clip, as used for Kimi K2. [07.2]
- **MXFP4** — the MX format with E2M1 elements: 4 + 8/32 = 4.25 bits per value; gpt-oss's MoE weight format. [08.1]
- **Native Sparse Attention (NSA)** — DeepSeek's sparse attention that combines a compressed view of the past, top-n selected blocks and a sliding window, mixed by learned gates. [05.2]
- **Needle-in-a-haystack (NIAH)** — an evaluation that hides one fact in long filler text and asks for it back; it measures retrieval, often by literal matching, not use of the context. [04.1]
- **Newton–Schulz iteration** — a matrix-multiplication-only iteration X ← aX + (b XXᵀ + c (XXᵀ)²) X that maps each singular value s to as + bs³ + cs⁵ and pushes them towards 1 without an SVD. [07.1]
- **Noise floor** — the seed-to-seed standard deviation of a metric for a fixed recipe; differences below it cannot be attributed to a change. [01.4]
- **NoPE** — attention without any positional encoding; order is inferred through the causal mask. [04.2]
- **NTK-aware scaling** — context extension that raises the RoPE base to b·s^(D/(D−2)), leaving the fastest pair unchanged and dividing the slowest by s. [04.2]
- **NVFP4** — NVIDIA's 4-bit format: 16 E2M1 values share an E4M3 scale, plus one FP32 scale per tensor; 4.5 bits per value. [08.1]
- **Observational scaling law** — a fit across many existing models (different families) that maps their benchmark scores to a few principal components and predicts other capabilities from them (Ruan et al.). [11.2]
- **Online (current) scaling** — computing each scale from the tensor being quantised, as opposed to delayed scaling from a history of earlier amax values. [08.2]
- **Online-softmax merge** — combining two attention results over disjoint keys using their log-sum-exps: lse = log(e^a + e^b), o = e^(a-lse)·o_a + e^(b-lse)·o_b. [09.1]
- **Optical circuit switch (OCS)** — the reconfigurable optical switches that join TPU v4's 4 × 4 × 4 cubes into slices of chosen shape. [09.5]
- **Over-training** — training a model on many more tokens per parameter than the compute-optimal ratio, which costs extra training compute and buys a smaller, cheaper-to-serve model. [11.1]
- **Overlong filtering / soft overlong punishment** — DAPO's two treatments of long responses: drop truncated responses from the loss, or a length penalty that grows linearly over the last L_cache tokens of the budget. [12.3]
- **p-RoPE** — keeping RoPE's fastest fraction p of standard frequencies and setting the slowest to zero (Barbero et al.; Transformers' `proportional` type). [04.2]
- **Paired bootstrap** — resampling the shared evaluation items to get an interval for the mean difference between two systems scored on the same items. [01.4]
- **Parallel MTP heads (Meta)** — n output heads on a shared trunk, each predicting one of the next n tokens from the same hidden state; parameter-matched by removing n − 1 trunk layers. [06.1]
- **Partial RoPE** — rotary embedding applied to only a prefix of each head's channels, leaving the rest position-free. [03.4]
- **pass@k (unbiased)** — 1 - C(n-c, k) / C(n, k) from n samples with c correct, the probability that at least one of k samples is correct. [12.4]
- **Per-Layer Embeddings (PLE)** — Gemma 3n's per-token, per-layer embedding table that can be kept and computed on the CPU, so only the core weights need accelerator memory. [06.5]
- **Pipeline bubble** — the fraction of device time idle because a stage waits for others; (p-1)/(m+p-1) for GPipe and 1F1B. [09.2]
- **Planted positive control** — known items inserted into a copy of the data to measure a checker's recall before trusting its zeros. [10.1]
- **Polar factor (UVᵀ)** — the orthogonal matrix nearest to G = USVᵀ; what an exact orthogonalisation of the update returns. [07.1]
- **Policy staleness** — the number of updates between the policy that sampled a batch and the policy being trained on it. [12.3]
- **Position Interpolation (PI)** — context extension that divides every RoPE frequency (equivalently every position) by the scale factor s. [04.2]
- **Post-training quantisation (PTQ)** — rounding a trained model's weights once, with no further training. [08.3]
- **Pre-registration** — writing the prediction, its interval and the decision rules down (here hashed and timestamped) before the run they are about. [11.3]
- **Prediction band** — the predicted interval of the validation loss at each fraction of the target run's schedule, used to stop a run that goes off track. [11.3]
- **Probe set** — hand-made responses that try a verifier's loopholes (answer repeated, embedded, unfinished, reformatted), scored before any RL run trusts the verifier. [12.1]
- **QK-Clip** — Kimi K2's per-head rescaling of the query and key projection weights after each optimizer step, by γ = min(1, τ/S_max), so the batch's largest logit would be at most τ; for MLA only the head-specific parts are scaled. [07.2]
- **QK-norm** — RMS-normalising each head's queries and keys (with learned gains) before the dot product, which bounds attention logits by the gains. [03.3]
- **QKV clamping** — clamping the query, key and value projections to [−c, c] (OLMo-1.7-7B: c = 8); bounds logits by c²√d. [07.5]
- **Quality classifier** — a cheap model that scores documents for a quality judgement (an LLM's labels, or "looks like a reference source") so the pipeline can keep the best-scoring fraction. [10.2]
- **Quantile threshold** — FineWeb2's way to move a filter threshold to another language: remove the same fraction of that language's documents as the English threshold removes of English. [10.6]
- **Quantisation-aware training (QAT)** — training with quantised weights (or activations) in the forward pass and high-precision master weights, so the model adapts to the rounding. [08.3]
- **Quintic Newton–Schulz coefficients** — Jordan's (3.4445, −4.7750, 2.0315), chosen for a large slope at zero; five steps leave singular values in a band around 1 (about 0.68–1.13), not at 1. [07.1]
- **Random Hadamard transform (RHT)** — multiplying blocks of values by a Hadamard matrix with random signs, an orthogonal map that leaves a GEMM unchanged in exact arithmetic but spreads outliers before quantisation; NVFP4 applies it to Wgrad inputs. [08.3]
- **Rank order (placement)** — the order of parallel dimensions from innermost (consecutive ranks) to outermost; decides which groups stay inside a node. Llama 3 uses [TP, CP, PP, DP]. [09.1]
- **Re-warm** — raising the learning rate again to continue training a model whose schedule already decayed. [07.4]
- **Recurrent depth** — iterating a shared core block a variable number of times per token, with a prelude and coda, to scale test-time compute without emitting tokens. [06.7]
- **Recurrent state** — the fixed-size matrix a linear-attention layer carries from token to token; it is what such a layer's decode cache holds. [05.1]
- **RegMix** — choosing a mixture by regressing target loss on mixture weights over many tiny proxy runs and optimising the regression (Liu et al.). [10.4]
- **Rehydration** — upsampling deduplicated documents by weights derived from their duplicate-cluster size and the filter's removal rate at that size (FineWeb2). [10.6]
- **Rephrasing** — rewriting existing documents with a language model into another style or form (encyclopedic, question-answer) to add training data with the same content. [10.3]
- **Replay** — keeping a share of the original training distribution in a continued-training mix to limit forgetting. [10.5]
- **Repository-level split** — assigning every file or task of a repository to the same split, so near-copies inside a repository cannot cross it. [10.6]
- **Resharding on load** — restoring a checkpoint saved under one parallel layout into a different one (other rank count or parallelism). [09.4]
- **Retention guard** — the largest regression accepted for a component, stated before the run; the component regresses if its interval's lower bound is below minus the guard. [12.4]
- **Reward model** — a model trained to score responses so that score differences predict preferences; its absolute scores carry no meaning. [12.1]
- **Reward over-optimisation** — the proxy reward keeps rising while the true (gold) reward peaks and falls as the policy moves away from the data the proxy was trained on. [12.1]
- **Ridge point** — peak FLOP/s divided by memory bandwidth (about 295 FLOP/byte for an H100 SXM in BF16): the intensity where compute and memory limits meet. [02.1]
- **Ring attention** — causal attention over a sequence split across devices, passing key/value blocks around a ring and merging partial results with the online-softmax rule. [09.1]
- **Rolling KV cache** — a cache that keeps only the last w keys and values of a local layer, trimmed after each step's attention. [03.2]
- **Roofline** — the bound min(peak FLOP/s, intensity × bandwidth) on attainable performance; an op's minimum time is max(FLOPs / peak, bytes / bandwidth). [02.1]
- **RoPE wavelength** — 2π/θᵢ tokens: the distance over which channel pair i of RoPE completes one rotation. [04.2]
- **Run card** — `run_card.yaml` per run: code version, config, arguments, seeds, data hashes, hardware, software and budget. [01.5]
- **Same-document context** — how many earlier tokens of a training window belong to the same document as a given token. [04.3]
- **Saturation** — clamping a value that exceeds the format's largest value to that value (instead of overflowing to infinity or NaN). [08.1]
- **Scale (quantisation scale)** — the higher-precision number s with x ≈ s · q that maps a group of values onto a low-precision grid; usually amax / (format maximum). [08.1]
- **Scaling Book sharding notation** — A[I_X, J]: dimension I sharded over mesh axis X, J replicated; each mesh axis used by at most one dimension. [09.5]
- **Scaling law** — a fitted function that predicts a run's loss (or another metric) from its size, tokens or compute, used to extrapolate from cheap runs to an expensive one. [11.1]
- **Scientific / nuisance / fixed hyperparameters** — the ones whose effect is measured / the ones re-optimised per arm for fairness / the ones held constant, whose values become caveats (Google tuning playbook). [01.3]
- **Self time / total time** — a profiled operator's time excluding / including the operators it calls. [02.2]
- **Self-speculative decoding** — drafting tokens with a model's own extra prediction modules and verifying them with its main head in one forward pass; with greedy verification the output equals plain greedy decoding. [06.1]
- **Sequence parallelism (SP)** — splitting the activations between tensor-parallel regions along the sequence, replacing TP's all-reduces with all-gathers and reduce-scatters. [09.1]
- **Sequence-level ratio (GSPO)** — the length-normalised ratio (pi_theta(y)/pi_old(y))^(1/|y|), the geometric mean of the token ratios. [12.3]
- **Sequential MTP modules (DeepSeek-V3)** — D modules, each combining the previous depth's hidden state with the embedding of the token k positions ahead through a projection and one transformer block, so every prediction keeps the complete causal chain. [06.1]
- **Share-alike** — a licence condition (for example CC BY-SA) that requires derived material to carry the same licence. [10.1]
- **Short-context regression** — the change in short-context quality (Eval v0) caused by a long-context change, measured against the model it came from on the same items. [04.1]
- **Silent data corruption (SDC)** — hardware producing wrong numbers without an error; detected by deterministic replay and checksums (Gemini 2.5) rather than by crashes. [09.4]
- **Sinkhorn-Knopp iteration** — exponentiate a matrix and alternately normalise its columns and rows; converges to a doubly-stochastic matrix (mHC uses t_max = 20). [06.2]
- **Slice-granularity elasticity** — continuing synchronous training on fewer TPU slices after a local failure instead of waiting for a replacement (Gemini 2.5). [09.4]
- **Sliding-window (local) attention** — attention in which each query sees only the last w keys, itself included; its cache never exceeds w tokens per layer. [03.2]
- **Source record** — the provenance of one training source: dataset, config and pinned revision, licence and its obligations, the command that prepared it, counts and file hashes. [10.1]
- **Spectral condition** — the requirement (Yang, Simon, Bernstein) that spectral norms of weights and their updates scale like √(fan_out/fan_in) for feature learning at any width. [07.3]
- **Stage D base model** — the pinned open base model the post-training modules start from: Qwen3-1.7B-Base at revision ea980cb. [12.1]
- **Staged context extension** — continued training at increasing sequence lengths, each stage gated by short-context recovery and long-context checks. [04.3]
- **Standard parametrization (SP)** — every weight initialised with one fixed scale and trained with one learning rate, whatever the width. [07.3]
- **Stochastic rounding** — rounding up with probability equal to the fractional distance to the lower neighbour, so the expected result equals the input; unbiased but noisy. [08.1]
- **Straight-through estimator (STE)** — treating a rounding function as the identity in the backward pass, so gradients reach the master weights. [08.3]
- **Tensor parallelism (TP)** — splitting every weight matrix of a layer over devices (by columns, then rows), with activation collectives inside every layer; kept inside a node. [09.1]
- **Tested-capability matrix** — per framework feature and architecture: documented, composed (ran and passed a correctness check), failed, or untestable here. [09.3]
- **Token accounting** — tokens, windows, epochs and documents supplied by each source of a mixture over a run. [10.1]
- **Tokenizer fertility** — tokens a tokenizer needs per byte or per word of text; high for languages it was not trained on. [10.6]
- **torch.distributed.checkpoint (DCP)** — PyTorch's sharded checkpoint format and API; each rank writes its shards, metadata records global shapes and offsets, and loading reshards to the current layout. [09.4]
- **torchao Float8** — PyTorch's FP8 training path (`convert_to_float8_training`), with tensorwise, rowwise and rowwise_with_gw_hp recipes. [08.2]
- **Transfer test** — a learning-rate (or other hyperparameter) sweep at several widths under each parametrization, with a pre-stated rule for how far the optimum may move. [07.3]
- **Truncated importance sampling (TIS)** — weighting tokens by min(pi_trainer / pi_sampler, C) to correct for a rollout engine whose probabilities differ from the trainer's. [12.3]
- **Truncation** — a response that reached the token budget without EOS; its reward says nothing about where the reasoning was going. [12.3]
- **Tuning budget** — the hyperparameter search each arm receives; a fair comparison gives the baseline the same budget as the new method. [01.3]
- **Two-step prediction** — predicting a downstream metric by first predicting a task loss from scale, then mapping task loss to the metric with a fitted sigmoid (Llama 3, OLMo ladder). [11.2]
- **Underflow (flush to zero)** — a nonzero value that becomes zero after scaling and rounding because it is below the scaled grid's smallest step. [08.1]
- **Update-RMS matching** — scaling Muon's orthogonalised update by 0.2·√max(A, B) so its entries have RMS ≈ 0.2, AdamW's typical range, letting Muon reuse AdamW's learning rate and weight decay (Moonlight Eq. 4). [07.2]
- **Update-to-weight ratio** — RMS of one optimizer step's change to a matrix divided by the RMS of the matrix; jumps when the learning rate or optimizer state is wrong. [07.5]
- **Verifiable reward** — a reward computed by a program from the response and ground truth (exact match, unit tests, a format rule); RLVR is RL with such rewards. [12.1]
- **Verifier false positive** — a wrong response the verifier accepts: the opening a policy can exploit. Measured against the specification on a probe set and on the policy's samples. [12.1]
- **Weight absorption** — folding MLA's key up-projection into the query (and the value up-projection into the output) so attention runs directly over cached latents without building per-head keys or values. [03.1]
- **Winner's curse (selection bias)** — selecting branches because their noisy measured gains were large keeps lucky draws, so the selected gains overstate the true ones. [06.3]
- **Within-document window** — a training window drawn entirely from inside one document at least as long as the window. [04.3]
- **WSD schedule (warmup-stable-decay)** — linear warmup, a constant learning rate for as long as wanted, then a decay over a chosen number of steps from a chosen step. [07.4]
- **WY representation (UT transform)** — the rewriting of a chunk of delta-rule updates as one unit-lower-triangular linear system, which turns a product of Householder-like matrices into matrix multiplications. [05.1]
- **YaRN** — per-frequency RoPE scaling: pairs that rotate more than β times over the trained length are kept, pairs that rotate fewer than α times are interpolated, those in between blended; plus an attention temperature (0.1 ln s + 1 on q and k). [04.2]
- **Young's interval** — the first-order optimal compute time between checkpoints, sqrt(2 · checkpoint time · MTBF). [09.4]
- **z-loss** — an auxiliary loss coef · (log Z)² on the output softmax normaliser (PaLM 10⁻⁴, OLMo 2 10⁻⁵) that keeps output logits from drifting. [07.5]
- **ZeRO stages** — sharding over data-parallel replicas the optimizer state (stage 1), also the gradients (stage 2), also the weights (stage 3, FSDP). [09.1]
- **Zero-bubble scheduling** — splitting the backward into the input gradient (B, on the critical path) and the weight gradient (W, deferrable) and filling idle slots with W. [09.2]
- **Zero-variance group** — a group in which every response got the same reward, so every advantage is zero and the prompt gives no policy gradient. [12.2]
- **µP (maximal update parametrization)** — width-dependent scalings of initialisation, learning rate and output multiplier that keep every layer's per-step activation change Θ(1) as width grows, so the best hyperparameters stop moving with width. [07.3]
- **µTransfer** — tuning hyperparameters on a small µP proxy and using them unchanged on the wide target model. [07.3]
