- **Test-time compute** — inference compute spent beyond one answer per query: longer reasoning, more samples, verification or search. [15.1]
- **Coverage (oracle pass@k)** — the probability that at least one of k samples is correct; an upper bound on any selection procedure, not an accuracy. [15.1]
- **Selection procedure** — a rule that picks one answer from several candidates without the gold answer: majority vote, best-of-N, weighted vote. [15.1]
- **Selection gap** — oracle pass@N minus the success of a selection procedure at N; the coverage the procedure cannot use. [15.1]
- **Majority vote (self-consistency)** — return the most frequent final answer among sampled reasoning chains (Wang et al. 2022). [15.1]
- **Best-of-N** — return the candidate with the highest verifier score. [15.1]
- **Weighted vote** — sum verifier scores over the candidates that give each answer and return the answer with the largest sum. [15.1]
- **Outcome reward model (ORM)** — a verifier that scores a complete response. [15.1]
- **Process reward model (PRM)** — a verifier that scores a partial solution step by step; trained on human step labels (PRM800K) or Monte Carlo estimates (Math-Shepherd). [15.1]
- **PRM-guided beam search** — keep the w best partial solutions by PRM score, expand each m times by one step, repeat; the verifier is called between every pair of steps. [15.1]
- **Budget forcing** — capping a reasoning chain by inserting the end-of-thinking delimiter, or extending it by suppressing the delimiter and appending "Wait" (s1). [15.1]
- **Policy-token equivalents (pte)** — a strategy's FLOPs divided by the FLOPs of one policy token: prefill + decode + (N_verifier / N_policy) × verifier tokens. [15.1]
- **Prefix caching** — reusing the KV cache of a shared prompt across samples or requests, so the prompt is prefilled once (vLLM automatic prefix caching, SGLang RadixAttention). [15.1]
- **Verifier over-optimisation** — best-of-N accuracy falling as N grows because the argmax selects the verifier's most confident false positives. [15.1]
- **Speculative decoding (speculative sampling)** — a draft proposes several tokens, the target verifies them in one pass, and a rejection rule keeps the output distributed exactly as the target's. [15.2]
- **Acceptance rate (alpha)** — the expected probability that a draft token is accepted; alpha = E[sum_x min(p, q)] = 1 − E[TV(p, q)]. [15.2]
- **Residual distribution** — norm(max(0, p − q)), from which a token is drawn at the first rejected position. [15.2]
- **Bonus token** — the extra token sampled from the target after all drafts of a round are accepted. [15.2]
- **Draft cost ratio (c)** — the time of one draft step divided by the time of one target decode step. [15.2]
- **EAGLE head** — a one-layer draft that autoregresses on the target's top-layer features plus the next token's embedding; EAGLE-3 fuses several layers' features and trains with training-time test. [15.2]
- **Training-time test** — training a draft head on its own predicted inputs, as it will see them when drafting several tokens (EAGLE-3). [15.2]
- **MTP as a draft** — using a model's multi-token-prediction module, trained with the model, as its speculative draft (DeepSeek-V3: 85–90% second-token acceptance). [15.2]
- **Cache rollback** — truncating a KV cache to the accepted prefix after verification, so rejected drafts leave no state. [15.2]
- **Prefill** — processing a prompt's tokens in one forward pass; compute-bound for prompts longer than the GPU's ridge point. [15.3]
- **Decode** — generating one token per sequence per step with the KV cache; memory-bound at small batch. [15.3]
- **KV capacity** — the number of sequences whose caches fit next to the weights in HBM at a given context length. [15.3]
- **Continuous batching** — adding and removing sequences from the running batch at every iteration of the engine. [15.3]
- **Chunked prefill** — splitting a long prompt's prefill across iterations that also carry the running decodes, so decodes do not stall (Sarathi-Serve). [15.3]
- **Prefill-decode disaggregation** — running prefill and decode on different GPUs and sending the KV cache between them (DistServe, Splitwise, Mooncake). [15.3]
- **TTFT / TPOT** — time to first token; time per output token after the first. [15.3]
- **Goodput** — the rate (or fraction) of requests that meet both the TTFT and the TPOT objective. [15.3]
- **Decode stall** — a decode step delayed by a long prefill in the same iteration, visible in the tail of TPOT. [15.3]
- **Rollout wave** — a group of RL rollouts decoded together, limited by KV capacity and paced by its longest response. [15.3]
- **Asymmetric quantisation** — quantisation with a scale and a zero point per group, mapping [min, max] onto the integer grid. [15.4]
- **KIVI layout** — KV quantisation with keys per channel, values per token and a full-precision residual window of recent tokens. [15.4]
- **Residual window (KV quantisation)** — the most recent tokens kept in full precision while older ones are quantised. [15.4]
- **Round-to-nearest (RTN) weight quantisation** — rounding each weight group to the grid without calibration; the baseline GPTQ and AWQ improve on. [15.4]
- **FP8 KV cache** — storing keys and values in an 8-bit float format with per-tensor scales (vLLM `--kv-cache-dtype fp8`). [15.4]
