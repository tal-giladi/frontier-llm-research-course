- **E4M3** — the FP8 format with 4 exponent and 3 mantissa bits (bias 7): largest value 448, smallest normal 2^-6, smallest subnormal 2^-9, no infinities, one NaN pattern; the usual format for weights and activations. [08.1]
- **E5M2** — the FP8 format with 5 exponent and 2 mantissa bits (bias 15): largest value 57,344, IEEE infinities and NaNs; more range, less precision than E4M3; traditionally used for gradients. [08.1]
- **E2M1 (FP4)** — the 4-bit float with values ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}; usable only with a scale per small block of values. [08.1]
- **E8M0 / UE8M0** — an 8-bit unsigned exponent with no mantissa, storing a power-of-two scale 2^(E − 127); the scale format of the OCP MX formats and of DeepSeek-V3.1. [08.1]
- **Binade** — the range [2^k, 2^(k+1)); a binary float has evenly spaced values inside each binade, 2^(k − m) apart for m mantissa bits. [08.1]
- **Scale (quantisation scale)** — the higher-precision number s with x ≈ s · q that maps a group of values onto a low-precision grid; usually amax / (format maximum). [08.1]
- **amax** — the largest absolute value of the group of elements that share a scale. [08.1]
- **Block scaling** — one scale per small group (a row, a 1 × 128 tile, a 128 × 128 or 16 × 16 block, 32 or 16 consecutive values) instead of per tensor, so one outlier affects only its group. [08.1]
- **Microscaling (MX) formats** — OCP's MXFP8, MXFP6, MXFP4 and MXINT8: 32 elements share one E8M0 power-of-two scale (OCP MX v1.0). [08.1]
- **MXFP4** — the MX format with E2M1 elements: 4 + 8/32 = 4.25 bits per value; gpt-oss's MoE weight format. [08.1]
- **NVFP4** — NVIDIA's 4-bit format: 16 E2M1 values share an E4M3 scale, plus one FP32 scale per tensor; 4.5 bits per value. [08.1]
- **Underflow (flush to zero)** — a nonzero value that becomes zero after scaling and rounding because it is below the scaled grid's smallest step. [08.1]
- **Saturation** — clamping a value that exceeds the format's largest value to that value (instead of overflowing to infinity or NaN). [08.1]
- **Stochastic rounding** — rounding up with probability equal to the fractional distance to the lower neighbour, so the expected result equals the input; unbiased but noisy. [08.1]
- **Fprop / Dgrad / Wgrad** — the three GEMMs of a linear layer in training: the forward product, the gradient with respect to the input, and the gradient with respect to the weight; each contracts over a different dimension. [08.2]
- **Fine-grained quantisation (DeepSeek-V3)** — FP8 with 1 × 128 activation tiles (128 × 1 in the backward pass) and 128 × 128 weight blocks, E4M3 everywhere, FP32 scales. [08.2]
- **Online (current) scaling** — computing each scale from the tensor being quantised, as opposed to delayed scaling from a history of earlier amax values. [08.2]
- **FP32 promotion (N_C)** — adding a GEMM's partial sum to an FP32 accumulator every N_C elements (128 in DeepSeek-V3) because the tensor-core FP8 accumulator keeps only about 14 bits. [08.2]
- **torchao Float8** — PyTorch's FP8 training path (`convert_to_float8_training`), with tensorwise, rowwise and rowwise_with_gw_hp recipes. [08.2]
- **Emulation (of a low-precision format)** — reproducing a format's rounding exactly in a higher-precision dtype; it measures numerics, never speed. [08.1]
- **Random Hadamard transform (RHT)** — multiplying blocks of values by a Hadamard matrix with random signs, an orthogonal map that leaves a GEMM unchanged in exact arithmetic but spreads outliers before quantisation; NVFP4 applies it to Wgrad inputs. [08.3]
- **2-D weight scaling** — one scale per square block (16 × 16 in NVFP4) so a weight and its transpose quantise identically and the forward and backward passes see the same weight. [08.3]
- **Quantisation-aware training (QAT)** — training with quantised weights (or activations) in the forward pass and high-precision master weights, so the model adapts to the rounding. [08.3]
- **Post-training quantisation (PTQ)** — rounding a trained model's weights once, with no further training. [08.3]
- **Straight-through estimator (STE)** — treating a rounding function as the identity in the backward pass, so gradients reach the master weights. [08.3]
- **Fake quantisation** — quantise-then-dequantise in a higher-precision dtype, so a model computes with low-precision values without low-precision kernels. [08.3]
- **Effective parameter count (N_eff)** — in the precision scaling law, the parameter count a low-precision-trained model behaves like: N(1 − e^(−P/γ)). [08.4]
- **Compute-optimal precision (P*)** — the training precision that minimises loss at fixed compute when parameters, tokens and bits are chosen together; about 7–8 bits in Kumar et al.'s integer-type fits. [08.4]
