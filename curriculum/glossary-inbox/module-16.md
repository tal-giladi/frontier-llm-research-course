# Module 16 glossary terms (for the main session to merge into glossary.md)

- **Agent environment** — a program an agent acts in over many turns, made of a task, tools, state, a verifier and a reset; in RL its verifier is the reward. [16.1]
- **Verifier** — the code that scores an episode from its final state; in agentic RL it is the only definition of success the policy sees. [16.1]
- **False accept (verifier)** — a wrong or loophole submission that the verifier rewards; the rate at which reward flows to behaviour nobody wanted. [16.1]
- **False reject (verifier)** — a correct submission that the verifier does not reward, for example tests that filter out valid solutions. [16.1]
- **Candidate registry** — a table of submissions with known right verdicts (correct, wrong, loophole) on which every verifier is tested; new candidates are added with `register` without editing the environment. [16.1]
- **Visible pairs / hidden cases** — the input/output examples the agent can see, and the ones only the verifier holds. [16.1]
- **Lookup-table overfit** — a submission that returns the expected outputs for the visible inputs and nothing useful elsewhere; it passes any verifier that checks only visible pairs. [16.1]
- **Property check** — a specification-level condition every correct output satisfies (for example, a clamped value lies in its interval), checkable without an expected value. [16.1]
- **Fresh inputs** — test inputs drawn at verification time from the task's generator with an unpredictable seed, so they cannot be memorised. [16.1]
- **Reset check** — reset, record the state, let an episode change it, reset again and compare; it proves something only if the episode really changed the state. [16.1]
- **Task synthesis (SWE-smith)** — generating software-engineering tasks by breaking working code and keeping only changes that make at least one passing test fail. [16.2]
- **Sibling tasks** — generated tasks from the same source code that share most of their code and often the same fix. [16.2]
- **Split unit** — the grouping (instance, function, file, repository, task family) a train/held-out split keeps together; it must match the claim. [16.2]
- **Sibling leak** — the share of held-out tasks that have a sibling in training; a memorising solver's held-out success tracks it. [16.2]
- **Observation tokens** — tokens an environment inserts into a multi-turn episode; the policy reads them as context but did not sample them. [16.3]
- **Action mask / response mask** — the per-token mask that is 1 on policy-sampled tokens and 0 on inserted observation tokens; the policy loss uses only the 1s. [16.3]
- **Retrieved-token masking** — Search-R1's name for leaving retrieved text out of the RL loss. [16.3]
- **Outcome credit** — one advantage per episode, given to every action token of every turn. [16.3]
- **Turn credit (return-to-go)** — each turn's tokens get an advantage from the rewards of that turn and later ones, so a per-turn reward reaches only the turns at or before it. [16.3]
- **Shaped reward** — an extra per-step reward added to guide learning; it is a new objective and can be optimised for its own sake. [16.3]
- **Context policy** — the rule for what earlier turns stay in an agent's context (full history, a window, summaries); the trainer must score actions under the same contexts. [16.3]
- **Reward hacking** — a policy earning reward through a flaw or misspecification of the reward instead of doing the intended task. [16.4]
- **Misspecified reward** — a reward that can be earned without the intended behaviour, for example one for format alone, for length, or for matching the visible examples. [16.4]
- **Gold check** — a check of the intended behaviour that the run logs but never trains on, used to detect a proxy that moves alone. [16.4]
- **Proxy-gold divergence** — the gain of the training reward minus the gain of the gold check over a run; large and positive signals a loophole. [16.4]
- **Output monitor** — a detector that looks at what the outputs are (kinds, length, literals of the expected answers), not at how they score. [16.4]
- **Inoculation prompting** — framing an undesired behaviour as acceptable during training, reported to stop it generalising to broader misalignment even when the behaviour itself is learned. [16.4]
- **Obfuscated reward hacking** — hacking that continues while its intent disappears from the chain of thought, reported when a CoT monitor is optimised against too strongly. [16.4]
- **Monitorability tax** — the performance given up by not optimising the chain of thought directly, so that it stays useful for monitoring. [16.4]
- **Execution-based evaluation (computer use)** — scoring an agent by checking the final state of the machine with task-specific scripts, as OSWorld does. [16.5]
- **Infeasible task (OSWorld)** — a task that cannot be done (deprecated or invented features); answering FAIL scores it as a success, so an always-FAIL agent scores 8.1%. [16.5]
- **Native GUI agent** — one model that maps screenshots directly to keyboard and mouse actions, as UI-TARS does, rather than a general model wrapped in prompts. [16.5]
